# Security Review — 五段式安全审查

对指定范围（目录 / diff / 文件清单 / 整个工作区）执行结构化安全审查，产出**带置信度的发现清单**，不瞎报、不漏报关键面。

**范围优先级**：用户显式指定的路径/diff > 未暂存改动（git diff）> 最近提交 > 整个工作区。开始前先向用户确认审查范围与深度（快速扫描 / 标准审查 / 深度审查）。

## 第 1 段：上下文调研

先建地图再动手，禁止一上来就逐文件乱翻：

1. 确定审查范围的入口点：`list_dir` 看结构，`grep` 定位关键面。
2. 识别资产面：入参处理（HTTP handler / channel 入站 / exec 参数）、文件读写边界、网络出口、凭据与密钥的存放/流转、进程/命令构造点。
3. 识别信任边界：工作区内/外、用户输入到危险操作的路径、序列化边界。
4. 产出：一张简短的「攻击面清单」（入口 → 危险汇 sink 的候选路径），后续段落逐条核对。

## 第 2 段：对比分析

把候选路径对照已知危险模式库逐条核对：

- **注入类**：命令注入（shell 拼接）、SQL/路径注入、prompt 注入（用户/工具输出未经隔离直接进上下文）、格式串。
- **边界类**：工作区逃逸（`..`、绝对路径、符号链接、8.3 短名）、SSRF（用户可控 URL 直连）、越权（缺属主/权限校验）。
- **凭据类**：硬编码密钥、日志泄密、错误消息回显敏感值、凭据落盘未加密。
- **资源类**：无上限循环/递归、无超时外呼、无配额的并发 spawn。
- **验证绕过**：magic byte / 校验和 / 签名验证被条件绕过、fail-open（验证失败仍继续）。

对照时读真实代码确认数据流（入口参数如何到达 sink），不做「看起来像」级别的推断。

## 第 3 段：漏洞评估

对第 2 段确认的候选逐条评估并记录：

- **位置**：`文件:行号`（可点击引用）。
- **数据流**：污点从哪进、经过哪些清洗、为何仍可达（或确认清洗有效 → 降级为「已防护」记录）。
- **触发条件**：需要什么输入/配置/权限才能触发。
- **影响**：机密性/完整性/可用性哪个受损，最坏情形是什么。
- **风险级**：CRITICAL / HIGH / MEDIUM / LOW（对齐系统安全层四级语义：CRITICAL=进程执行/系统级破坏，HIGH=写/删/越界，MEDIUM=编辑/信息泄露，LOW=读/枚举）。
- **已防护说明**：若路径上有有效缓解（参数校验、白名单、沙盒、审批闸），如实记录缓解层——防御纵深成立的不算漏洞。

## 第 4 段：子代理并行证伪

用 `spawn` 为每个 **HIGH 及以上**的发现派一个证伪子代理（`label` 用 `sec-review-证伪-<序号>`），任务是**尝试推翻这个发现**：

- 子代理提示词要素：发现全文（位置/数据流/触发条件）+ 指令「你的唯一目标是证伪它：找出审查者遗漏的清洗层、不可达路径、错误的前提假设；给出 CONFIRMED（成立）/ REFUTED（不成立）/ UNCERTAIN（证据不足）三值结论 + 论据」。
- 多个发现并行派发（一次消息里多个 spawn 调用）。
- 收齐结论后，REFUTED 的发现降级为「已排除（附论据）」，不进最终清单正文。

单发现审查（快速扫描模式）可跳过本段，但在报告中注明「未经证伪」。

## 第 5 段：置信度过滤与报告

按证伪结论过滤后输出结构化报告：

```
## 安全审查报告（<范围>，<模式>）

### 发现（按风险降序）
#### [CRITICAL] <一句话标题>
- 位置：`path:line`
- 数据流：...
- 触发条件：...
- 影响：...
- 证伪结论：CONFIRMED — <论据摘要>
- 建议修复方向：<思路，不代写补丁除非用户要求>

### 已排除（证伪不成立）
- <发现> — REFUTED：<论据一句话>

### 已防护（有缓解层的路径）
- <路径> — 缓解层：<校验/沙盒/审批说明>

### 未覆盖面（诚实声明）
- <本次审查没看到的地方：二进制依赖、运行时配置、需要凭据的外部服务…>
```

**置信度规则**：CONFIRMED 才进「发现」正文；UNCERTAIN 的单列「待人工确认」节并写明缺什么证据；不凑数——没有发现就明说「本次未发现达阈值的问题」并列出已检查的攻击面。

## 边界与纪律

- **只读审查**：本技能默认只 `read_file`/`list_dir`/`grep`/`git`，不修改被审查代码；写 PoC 文件需用户明确同意且只落在工作区临时目录。
- **不外传**：发现的凭据/密钥在报告中只出现指纹（前 4 后 4 字符），不出现完整值。
- **不自判风险放行**：报告归报告，是否修复、如何修复由用户决定；不要因为「低风险」就自作主张跳过报告。
- 与系统安全 8 层的关系：本技能是**代码静态审查**，不替代运行时的注入检测/ABAC/审计链等防护层；发现的安全缺陷修复后仍由那 8 层兜底。
