拉起一个子代理在后台独立处理任务，不阻塞当前回合。

**用法要点**
- 子任务必须自包含：子代理看不到当前对话历史，任务描述要带全上下文（目标、背景、涉及路径、期望产出形态）。
- 适合可并行的独立探索、批量处理、大范围调查——派出去的同时自己继续主线工作。
- 子代理的产出会作为工具结果回来；对结果做核验后再采信，不要无检查转述。

**参数纪律**
- tools 档位：readonly（默认）只给只读工具，适合调查/研究；full 继承主代理工具集，只在子任务必须写文件/执行命令时用——能 readonly 就 readonly。
- role 角色：按任务性质选（explorer 调查 / planner 规划 / reviewer 评审 / debugger 排障等）；不选则按 tools 档位自动映射。
- background=true 长任务后台化，完成后结果自动回灌本会话。

**决策路由**
- 需要立刻拿到结果才能继续推理的短任务 → 不要 spawn，直接自己做更快。
- 任务会写文件且影响主线 → 权衡是否自己做（子代理写入不经你确认）。
- 跨节点的大任务 → `cluster_rpc` 派给集群节点，spawn 是本机子代理。

**约束与边界**
- 嵌套深度有限制：接近上限时自己完成，不要再派生。
- 子代理同样过安全 8 层管线与审批闸——spawn 不是安全旁路。
