增量读取 background_start 启动的后台任务输出：传 job_id，重复调用带上次的 next_offset 只取新字节。

**用法要点**
- 响应带 running/done 状态；任务已结束时附带退出码——用它判断后台命令是否成功，不要靠输出文本猜。
- 轮询间隔放温和（数秒级），别空转刷屏；等待启动就绪看关键标志（端口监听、就绪日志），不要盲等。
- 输出是累积的：next_offset 之前的字节不会重复返回，按返回里的下次偏移续读。

**决策路由**
- 任务卡住不动且确认无需继续 → `background_kill` 停掉，读已捕获的输出找根因。
- 需要在输出里搜特定错误 → 读到本地后用 `grep` 对存档文件搜，别靠肉眼逐页翻。

**约束与边界**
- 只读工具，无审批负担；job_id 不存在会诚实报错（任务可能已被清理）。
- 长时间无新输出不代表进程死了——结合 running 状态与进程行为判断，不要凭一次空读就 kill。
