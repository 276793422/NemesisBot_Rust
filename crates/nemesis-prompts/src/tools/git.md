在工作区内运行 git 子命令：读操作自由用，安全写操作按需用，危险操作会被安全层拦审。

**用法要点**
- 了解仓库状态永远先跑读操作：status、diff、log、show、branch——改代码前先知道自己在什么基础上改。
- 安全写操作按需用：add、commit、branch_create、checkout、restore、stash。
- push、reset --hard、clean、rebase 等危险操作需要审批，会被转人工确认——这是设计行为，不是故障；被拦后向用户说明意图等确认，不要拆成多条「安全」命令变相达成同一效果。
- 提交信息写清楚做了什么，一行说事；不要在提交信息里替用户决定推送。

**决策路由**
- git 覆盖不了的一般命令（进程、系统操作）→ `exec`。
- 只想看某文件的历史或内容 → `read_file` + git log/show 组合足够，不用整仓操作。
- 需要语义级代码查询（引用、定义）→ `lsp`，git 不是搜索工具。

**约束与边界**
- 默认只在当前工作区仓库内操作；工作区边界开启时外部仓库操作受限。
- 用户没有明确要求时：不主动 commit、不主动 push、不建分支、不做 reset --hard——把仓库状态变更的决定权留给用户。
- 合并冲突拿不准时保留现场（git status + diff 汇报），不要强行择边了事。
