运行项目的构建/测试/lint 检查：回复只含 pass/fail 统计与去重错误签名，完整输出存档并给出路径。

**用法要点**
- 改完代码的验证闭环走这里，不要散跑命令再自己拼报告——它替你做输出去噪与错误去重。
- 需要看完整输出时按回复里的存档路径 `read_file`，错误签名不够定位时才去读全文。
- 检查失败逐个错误读：先修编译错，再修测试错；一次修一类，修完重跑验证，不要一次改五处然后不知道哪处修好了。

**决策路由**
- 检查范围之外的一次性命令（装依赖、查状态）→ `exec`。
- 需要交互式调试（断点、逐条跑）→ `exec` / `run_script` 自行组织。
- 检查全绿再交付；红着就交付是违约。

**约束与边界**
- 输出全文存档不进上下文——上下文里只留签名与统计，这是它不挤爆 token 的原因，别用 exec 绕过这个保护。
- 反复失败三轮没有新进展时停下来分析根因（读全文输出、缩小复现范围），不要同型命令无限重跑。
