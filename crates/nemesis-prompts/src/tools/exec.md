执行一条 shell 命令并等待完成，返回 stdout、stderr 与退出码。

**用法要点**
- 适合一次性命令：查看状态、装依赖、跑单条构建、调用 CLI 工具。
- 命令有超时上限（参数 timeout，默认 30 秒，可调大）；预期长时间运行或常驻的进程不要硬等，改用 `background_start`。
- Windows 上 PowerShell 的 `curl` 别名指向 `Invoke-WebRequest`，需要真 curl 时写 `curl.exe`。
- 预知输出很大（全量构建、长日志）时，先重定向到文件再用 `read_file`/`grep` 取需要的部分，避免超长截断丢信息。
- 命令失败先读 stderr 定位根因：缺依赖、路径错、权限不足各有不同修法；不要原样盲目重试，也不要连环换命令碰运气。

**决策路由**
- 编译/测试/lint 等项目验证 → `run_checks`（输出去噪 + 全文存档），不要散跑命令再自己拼报告。
- 读文件 → `read_file`；搜内容 → `grep`；列目录 → `list_dir`。不要拿 shell 拼 cat/grep/ls。
- 后台常驻（dev server、watch、长构建）→ `background_start`；启动后不需要看输出的程序 → `exec_async`。
- 多行脚本逻辑（变量、循环、条件分支）→ `run_script`，不要拼超长单行命令。

**约束与边界**
- 命令过安全管线：危险操作（大面积删除、外发数据、工作区外写入）会被拦截或转人工审批；被拦时如实向用户说明拦截原因，不要变换写法绕路重试。
- 破坏性命令（递归强删、批量杀进程、格式化）执行前确认用户知情。
- 工作区限制开启时，工作区外的写操作会被拒绝——这不是故障，是边界。
