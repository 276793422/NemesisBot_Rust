把文件中一段精确文本替换为另一段：old_text 必须与文件内容一字不差。

**用法要点**
- old_text 从 `read_file` 的实际输出复制，不要凭记忆重打；缩进、空格、转义字符逐字保留。
- old_text 取「足够长且唯一」的片段：太短会匹配多处导致歧义，太长容易抄错；优先包含独特标识符（函数名、变量名）。
- 没先读文件就编辑会被拒绝（系统强制先读后改）。
- new_text 传空串即删除该片段；替换后自己重读一遍确认改动落对位置。

**决策路由**
- 同一批联动修改（重命名符号 + 改全部调用点、多处同型小改）→ `multiedit`，原子生效、无中间态。
- 新建文件或整文件重写 → `write_file`；只在文件末尾追加 → `append_file`。
- 不确定目标位置的上下文 → 先 `grep` 定位再 `read_file`，然后回来改。

**约束与边界**
- 写类操作过安全管线并受工作区边界约束；plan 模式下除 plans/ 目录外会被拦截。
- 代码改完跟着跑 `run_checks`（编译/测试/lint）闭环验证，不要改完就默认成功。
- 一个文件的多处修改尽量合并为一次 `multiedit` 调用，减少中间态暴露给并发读方。
