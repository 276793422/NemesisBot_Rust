按名字运行一个已注册工作流，返回执行 id、最终状态与各节点输出 JSON。

**用法要点**
- 名字来自已注册工作流清单；不确定有哪些可跑时先列（workflow 能力查询），不要凭记忆猜名字。
- 工作流适合「固定步骤的重复过程」：流程已定义好，触发后按 DAG 执行；每次执行有 id 可追溯。
- 拿到各节点输出后做核验与汇总，不要只看最终状态就下结论。

**决策路由**
- 没有现成工作流的一次性任务 → 直接用基础工具做；重复出现的流程 → 建工作流再触发。
- 需要推理与中间决策的任务 → `spawn` 子代理（工作流是预定义 DAG，不现场推理）。
- 多节点协作的看板任务 → `board_issue`。

**约束与边界**
- 工作流执行过安全管线；节点内的工具调用照常过审批与拦截。
- 执行失败读失败节点的输出定位原因，不要原样反复重跑。
